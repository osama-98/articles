Translatable Enums in Laravel

Stop hardcoding labels inside match blocks. The laravel-enum-translatable package gives PHP backed enums first-class translations, array helpers, and safe comparison — all through composable traits.

composer require osama-98/laravel-enum-translatable PHP 8.2+ Laravel 11+

Enums are the natural home for fixed sets of states — OrderStatus, CourseStatus, Role. But the moment your app speaks more than one language, a question appears: where does the human-readable label live?

The usual answer hardcodes a match statement inside the enum, or scatters __() calls across Blade. Both bolt presentation onto a data type and break the day you add a locale. This package routes every label through Laravel's own translation files instead — the enum stays pure data, the words live in lang/.

Why The hardcoding trap

A match inside the enum couples your data type to one language.

The fixed sign: printing the label straight onto the enum is like welding an English-only sign to a door. Add Arabic and you must cut it off and re-weld. Better to hang a swappable card — the door stays the same, the card changes per reader.

Below, the label is welded in with match. Every new language reopens the enum and grows the block.

Before
OrderStatusEnum.php 
<?php

enum OrderStatusEnum: string
{
    case PENDING   = 'pending';
    case SHIPPED   = 'shipped';
    case DELIVERED = 'delivered';

    public function label(): string
    {
        return match($this) {
            self::PENDING   => 'Pending',   // English only —
            self::SHIPPED   => 'Shipped',   // adding Arabic means
            self::DELIVERED => 'Delivered', // rewriting this method
        };
    }
}

The cost: the enum now owns presentation. Every locale, every wording tweak, and every API shape forces an edit to a file that should only describe states.

1 Install & scaffold

One Composer command, then generate an enum with the artisan helper.

terminal 
# requires PHP 8.2+ and Laravel 11+
composer require osama-98/laravel-enum-translatable

# optional: scaffold a new enum class
php artisan make:enum OrderStatus

Apply the EnumTranslatable trait and declare your cases. No label() method — the words come from a language file.

app/Enums/OrderStatusEnum.php 
<?php

use Osama\LaravelEnums\Traits\EnumTranslatable;

enum OrderStatusEnum: string
{
    use EnumTranslatable;

    case PENDING   = 'pending';
    case SHIPPED   = 'shipped';
    case DELIVERED = 'delivered';
}

2 Put the words in lang/

The enum class name maps to a key. Each locale is just another file.

Labels are keyed by a snake-cased, pluralized version of the enum name — OrderStatusEnum → order_statuses. Add one file per language and translation is done.

lang/en/enums.php 
<?php

return [
    'order_statuses' => [
        'pending'   => 'Pending',
        'shipped'   => 'Shipped',
        'delivered' => 'Delivered',
    ],
];
lang/ar/enums.php 
<?php

return [
    'order_statuses' => [
        'pending'   => 'قيد الانتظار',
        'shipped'   => 'تم الشحن',
        'delivered' => 'تم التوصيل',
    ],
];

Why it helps: translators touch lang/ files, never your PHP. A new language is a new file — zero code changes, zero risk to the enum.

3 Read the label

trans() resolves the current locale; pass one to override; allTrans() returns every locale at once.

anywhere — controller, Blade, resource 
$status = OrderStatusEnum::PENDING;

$status->trans();              // 'Pending'  (uses app()->getLocale())
$status->trans('ar');          // 'قيد الانتظار'

// optional context — points at a sibling key for a longer string
$status->trans(context: 'description');
// 'This order is awaiting processing.'

// every supported locale in one call
$status->allTrans();
// ['en' => 'Pending', 'ar' => 'قيد الانتظار']

Why it helps: the same case renders correctly in any language without a single conditional. Switch app()->setLocale() and every label follows.

4 Ship it to the frontend

Turn a whole enum into translated value / name pairs — perfect for a dropdown or a JSON response.

The menu board: a select box needs both the stored value and the word the user reads. These helpers hand you both, already translated, in one call.

building a select / API payload 
// array of ['value' => ..., 'name' => ...] pairs
OrderStatusEnum::toArrayTrans('ar');
// [
//   ['value' => 'pending',   'name' => 'قيد الانتظار'],
//   ['value' => 'shipped',   'name' => 'تم الشحن'],
//   ['value' => 'delivered', 'name' => 'تم التوصيل'],
// ]

// same data, as a Laravel Collection for fluent chaining
OrderStatusEnum::toTransCollection()->pluck('name', 'value');

// a single case as a structured pair
$status->object();
// ['value' => 'pending', 'name' => 'Pending']

Why it helps: your API resource or form builder stops hand-rolling label loops. The enum already knows how to describe itself in the caller's language.

5 Pick the right trait

Three composable traits, layered — take only the power you need.

Not every enum needs translation. The traits stack from light to full, so you opt into exactly the surface you use.

three levels 
// 1. comparison + safe casting only
use EnumWrappable;

// 2. + array helpers (names, values, filtering, random)
use EnumArrayable;

// 3. + full translation (everything above, plus trans/allTrans)
use EnumTranslatable;

Why it helps: a pure-logic enum can grab EnumWrappable for safe comparison without dragging in a translation requirement it will never use.

6 Safe casting & comparison

Turn loose input into an enum, and compare without leaking ->value everywhere.

The bouncer: wrap() checks an unknown value at the door — a valid one becomes a case, anything else is turned away (or null in non-strict mode) instead of crashing deep in your code.

EnumWrappable helpers 
// cast a raw string/value into the enum — safely
OrderStatusEnum::wrap('pending');          // OrderStatusEnum::PENDING
OrderStatusEnum::wrap('unknown');          // null (strict: throws)

// readable comparisons — no manual ->value plumbing
$status->is('pending');                 // true
$status->isNot('shipped');              // true
$status->isAny(['pending', 'shipped']);  // true

Why it helps: request data, query strings, and webhook payloads become enums at the boundary — the rest of your code works with types, not loose strings.

7 Array utilities

List, filter, and sample cases with expressive helpers from EnumArrayable.

querying the case set 
OrderStatusEnum::names();    // ['PENDING', 'SHIPPED', 'DELIVERED']
OrderStatusEnum::values();   // ['pending', 'shipped', 'delivered']

// filter the set by value
OrderStatusEnum::only(['pending', 'shipped']);
OrderStatusEnum::except(['delivered']);

// wildcard matching
OrderStatusEnum::matching('ship*');     // [SHIPPED]
OrderStatusEnum::contains('end');       // [PENDING]

// random pick — handy for seeders & factories
OrderStatusEnum::randomCase(except: OrderStatusEnum::DELIVERED);

Why it helps: seeders, factories, dropdown subsets, and feature gates stop maintaining hand-written case lists that drift out of sync with the enum.

8 Configure (optional)

Publish the config to set supported locales or wire up a modular app.

terminal 
php artisan vendor:publish --tag="laravel-enums-config"

Key options in config/laravel-enums.php:

  • supported_locales — which locales allTrans() walks.
  • modular_enabled — resolve translations from module packages (e.g. nWidart/laravel-modules).
  • namespace_resolver — custom logic for the translation namespace.

In Short

Keep enums as pure data and move every human-readable word into Laravel's lang/ files. One trait, one language file per locale, and trans() does the rest.

You get translation (trans, allTrans, toArrayTrans), array tooling (names, values, only, matching, randomCase), and safe comparison (wrap, is, isAny) — composed from three layered traits so you take only what you need.

Adding a new language becomes a new file in lang/, not a rewrite of your code.
