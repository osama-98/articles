PSR Standards Explained

A simple walkthrough of every PHP Standards Recommendation with practical examples, organized by status.

● Accepted ● Deprecated ● Draft ● Abandoned

Accepted Standards 14

These are the active, recommended standards used in modern projects.

PSR-1

Basic Coding Standard

Accepted

Fundamental rules: name classes in StudlyCaps, methods in camelCase, and constants in UPPER_CASE.

basics.php 
class UserProfile {        // StudlyCaps
    const MAX_AGE = 120;     // UPPER_CASE
    public function getName() {} // camelCase
}
PSR-3

Logger Interface

Accepted

A unified interface for logging events and errors at different severity levels, so you can swap logging libraries without changing your code.

logger.php 
$logger->info('User logged in');
$logger->error('Database connection failed');
$logger->warning('Storage running low');
PSR-4

Autoloading Standard

Accepted

Maps a class name to a file path automatically, so you never write require by hand. This is the foundation of Composer.

autoload.php 
// The class:
namespace App\Models;
class User {}

// Expected file location:
// src/Models/User.php
PSR-6

Caching Interface

Accepted

An advanced caching system built around a Pool and Item objects, giving you fine-grained control.

cache-pool.php 
$item = $pool->getItem('user_42');
if (!$item->isHit()) {
    $item->set($userData);
    $pool->save($item);
}
PSR-7

HTTP Message Interface

Accepted

Represents HTTP requests and responses as objects. Messages are immutable, and it's used heavily when building APIs.

http-message.php 
$method = $request->getMethod();      // "GET"
$path   = $request->getUri()->getPath();
$code   = $response->getStatusCode();  // 200
PSR-11

Container Interface

Accepted

A unified interface for dependency-injection containers (DI Container) to fetch services and objects.

container.php 
if ($container->has('mailer')) {
    $mailer = $container->get('mailer');
}
PSR-12

Extended Coding Style Guide

Accepted

The full formatting spec: 4-space indentation, brace placement, spacing. It replaces the older PSR-2.

style.php 
class User
{
    public function getName(): string
    {
        return $this->name;
    }
}
PSR-13

Hypermedia Links

Accepted

A standard way to represent links in APIs (such as HATEOAS), where each link carries its target and relationship.

links.php 
$link->getHref();  // "/users/42"
$link->getRel();   // "self" or "next"
PSR-14

Event Dispatcher

Accepted

A unified event system: you dispatch an event, and the registered Listeners respond to it.

events.php 
// Fire an event after a new user registers
$dispatcher->dispatch(new UserRegistered($user));
PSR-15

HTTP Handlers (Middleware)

Accepted

Standardizes writing Middleware — layers that process a request before it reaches its destination (e.g. authentication checks).

middleware.php 
public function process($request, $handler)
{
    // validate, then pass to the next layer
    return $handler->handle($request);
}
PSR-16

Simple Cache

Accepted

A simpler take on PSR-6 with a direct get/set interface, ideal for everyday use.

simple-cache.php 
$cache->set('key', $value, 3600); // 1 hour TTL
$value = $cache->get('key', $default);
PSR-17

HTTP Factories

Accepted

Unified interfaces for creating PSR-7 objects (requests, responses, URIs) in a standard way.

factories.php 
$request = $factory->createRequest(
    'GET', 'https://api.example.com'
);
PSR-18

HTTP Client

Accepted

A unified interface for sending HTTP requests and receiving responses, so you can swap the underlying client without touching your code.

http-client.php 
$response = $client->sendRequest($request);
echo $response->getStatusCode(); // 200
PSR-20

Clock

Accepted

A unified interface for getting the current time, which makes code easy to test by mocking the clock.

clock.php 
$now = $clock->now(); // DateTimeImmutable

Deprecated Standards 2

Once accepted, but replaced by newer standards. Don't use these in new projects.

PSR-0

Autoloading Standard (old)

Deprecated

The first autoloading standard, which relied on underscores in class names. Replaced by PSR-4, which is simpler and cleaner.

PSR-2

Coding Style Guide (old)

Deprecated

The original code-formatting standard. Replaced by PSR-12, which extends it and adds rules for modern PHP features.

In Progress (Drafts) 4

Still under discussion and development, and may change before acceptance. Not ready to rely on yet.

PSR-5

PHPDoc Standard

Draft

Standardizes how documentation comments (DocBlocks) are written above functions and classes.

phpdoc.php 
/**
 * @param  int   $id
 * @return User
 */
PSR-19

PHPDoc Tags

Draft

A companion to PSR-5 that defines the standard list of tags such as @param, @return, and @throws.

PSR-21

Internationalization

Draft

A unified interface for translation, multi-language support, and locale formatting (dates, numbers, currencies).

PSR-22

Application Tracing

Draft

A unified interface for tracing application performance and observability across its components.

Abandoned Standards 3

Proposed but never completed or approved; work on them has stopped.

PSR-8

Huggable Interface

Abandoned

A tongue-in-cheek proposal for an interface that makes objects "huggable." It was never serious and never adopted. 🙂

PSR-9

Security Advisories

Abandoned

A proposal to standardize how security vulnerabilities are announced across projects. Never completed.

PSR-10

Security Reporting Process

Abandoned

A companion to PSR-9 defining how vulnerability reports are received and handled. Also never completed.

In Short

Standards are numbered from PSR-0 to PSR-22: of these, 14 are accepted and active, 2 are deprecated (replaced by newer ones), 4 are drafts in progress, and 3 were abandoned.

PSRs aren't hard rules enforced by the PHP engine — they're conventions the community follows voluntarily. Adopting them makes your project professional and interoperable with major libraries and frameworks.

Official, always up-to-date source: php-fig.org/psr
